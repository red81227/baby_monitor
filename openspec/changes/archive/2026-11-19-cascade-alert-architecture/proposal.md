# Proposal

## Why

`redesign-vision-architecture` 原本規劃以時序狀態估計器判斷寶寶狀態，本機 LLM 只當不在警報路徑上的摘要旁路（D7）。但只用影像規則很難判斷「狀況的原因」（例如只是翻身，或是真的醒來），也難以在不漏報的前提下減少誤報。改成兩段式：YOLO 便宜地持續篩選「有狀況」，本機 VLM 只在觸發時判斷原因並決定是否提醒。狀況的條件與門檻在沒有真實嬰兒影像前無法定案，因此必須做成上線後只改設定檔就能調整，並且調整時不會不小心把重要提醒關掉。

## What Changes

- 新增兩段式狀況判斷：第一段由 YOLO pose 與移動分數算出一組固定的「訊號」，依規則觸發「狀況」；第二段由本機 VLM 讀取事件前後的片段與 metadata，判斷原因並決定是否提醒
- 新增 VLM 定期巡檢：第一段訊號偵測不到的狀況（口鼻被蓋住：YOLO pose 沒有嘴巴關鍵點，被遮住的鼻子也會被推算為可見）由 VLM 每隔固定時間直接看畫面判斷；巡檢只能讓提醒發生，VLM 失效時產生「巡檢停止」系統警報
- 新增狀況規則檔：狀況的條件（訊號、比較、門檻、持續時間與容許中斷 `grace`，以 AND 組合）、路由（`direct` / `llm` / `suppress`）、嚴重程度、冷卻時間、LLM 片段長度與 prompt 都放在設定檔；修改規則不需要重新編譯
- 規則修改的安全機制：熱重載、驗證失敗時沿用舊規則並回報錯誤、規則版本號記入每筆觸發與警報、影子模式（只記錄不提醒）、離線重播評估、底線保護（`critical` 狀況不可被壓制、不可交給 LLM 決定是否提醒）
- 規則只能以修改檔案的方式變更；網頁只**顯示**目前規則、版本、載入錯誤、觸發紀錄、LLM 判定與警報，不提供編輯（網頁沒有認證）
- 新增環形緩衝與事件片段，作為 VLM 判定的輸入
- 新增警報：去重、冷卻、壓制，並在監視頁面顯示；其他通知管道待定
- 人物偵測改為在內部計算畫面中的人數（供「有大人進入」使用），對外仍只回報信心值最高的人物
- 初始狀況清單：臉被蓋住、趴睡、醒來持續活動、不在床上、有大人進入（壓制用）、靠近床邊；初始巡檢：口鼻被蓋住；哭聲留到之後加入音訊時處理
- 修訂 `redesign-vision-architecture`：改寫 D7（LLM 進入警報路徑）、更新整體架構圖、分期表與 capability 清單

### 不在範圍內

- 網頁編輯規則與認證
- 雲端模型或任何把影像送出本機的做法
- 選定特定 VLM 模型與通知管道（以 spike 決定，見 design.md 的 Open Questions）
- 嬰兒真實影像的評估（之後另外進行；躺床蓋被子實驗另開 change）

## Capabilities

### New Capabilities
- `situation-rules`: 訊號清單、狀況與巡檢規則檔的格式與語意（含容許中斷）、驗證與熱重載、版本、影子模式、底線保護、離線重播評估
- `situation-judgement`: VLM 判定：觸發後的輸入（片段 + metadata）、輸出（原因、是否提醒）、逾時與失效處理、只在本機執行；VLM 定期巡檢與巡檢停止的通知
- `event-recording`: 主碼流環形緩衝與依時間範圍取出事件片段
- `alerting`: 警報的產生、去重、冷卻、壓制與紀錄

### Modified Capabilities
- `person-detection`: 除了信心值最高的人物外，另外計算畫面中達到門檻的人數
- `status-api`: 新增規則、巡檢與警報狀態的查詢
- `web-dashboard`: 新增唯讀的規則、巡檢狀態、觸發紀錄、LLM 判定與警報顯示
- `runtime-configuration`: 新增規則檔路徑、VLM 端點、環形緩衝長度等設定

## Impact

- 程式碼：新增訊號計算、規則引擎、環形緩衝、VLM 用戶端、警報管理；`YoloDecoder` / `YoloDetector` 需計算人數；`AnalysisThread` 的偵測結果改為同時送給規則引擎
- 設定：新增規則檔（YAML）與 prompt 檔目錄；新增 `BM_*` 環境變數
- 依賴：YAML 解析函式庫；本機 VLM 執行環境（例如以 HTTP 呼叫的本機推論服務，由 spike 決定），可能與 YOLO 共用 GPU
- API：`/api/status` 新增欄位或新增唯讀端點；既有欄位不變
- 前端：監視頁面新增狀況 / 警報區塊
- 維運：事件片段與巡檢紀錄的磁碟空間與保留策略；VLM 服務必須常駐（口鼻被蓋住只靠巡檢偵測），需要啟停與監看；巡檢持續占用少量 GPU（約 2%）
- 文件：`redesign-vision-architecture` 的 proposal.md 與 design.md 同步修訂
